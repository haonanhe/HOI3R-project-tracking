Key discoveries

FINDING Training loss parity does NOT imply eval parity (cached -> ~16x metric gap)

Both runs converge to within 1.5% on every training-loss component (total 0.0330 vs 0.0335; point 0.0272 vs 0.0273; joint 0.0011 vs 0.0009; add_s 0.0022 vs 0.0007). But re-evaluating each checkpoint with a *live* frozen 4RC encoder gives full=4.15mm hand joint L2 / 2.29mm obj ADD-S, vs cached=66.99mm / 57.50mm. The cached run learned to fit feats that drift from the live forward.

FINDING Cached encoder is the right speed lever, NOT the right correctness lever

After encoder-pyramid precompute (~3 min for 63 frames), the cached path skips the frozen 4RC fwd and saves ~10% wall-clock per step. Functionally equivalent on the *training* loss curve. But the model overfits to numeric noise that doesn't survive a live re-forward, so for any deployable Plan-1 baseline we keep --encoder-mode every-step. Cached path is for ablation sweeps where eval recomputes a live forward off the same feats.

FIX d_kv must equal 2*HIDDEN, not HIDDEN

ArcEncoderWrapper concatenates local + global at 2*HIDDEN per token. Hoi3rV2Model's cross-attention requires d_kv=2*HIDDEN; passing d_kv=HIDDEN would crash on the very first cross-attn block. Fixed at module construction in p1_train / p1_eval / p1_train_cached.

FIX MANO 21-joint extraction = 16 base + 5 fingertip vert IDs

smplx returns 16 base joints; HOI3R appends fingertip vertices [320, 443, 672, 555, 744] (smplx-mano order: thumb, index, middle, ring, pinky) to recover the 21-joint OpenPose-compatible layout. This is the same convention used by V1 and the ghop benchmark loader.

Caveats

  • Eval is a single 16-frame anchor clip on a single sequence; not a held-out test split. Numbers are overfit metrics.
  • Cached vs full is not a controlled A/B — bs differs (16 effective vs 8) due to p1 quota at submit time. Compare on shape-of-curve, not a single number.
  • Hand point loss is a placeholder (won't supervise correctly); joint+edge+temporal losses provide the actual hand signal in P1.
  • Contact loss returns 0 in dev runs (warmup-at-500 + plumbing not finalized); excluded from total loss for now.
  • World-space rendering subsamples object cloud to 256 pts (from 1024) for crisper Plotly markers.
