Key discoveries

FINDING Per-frame extras get NO RoPE in stock Wan2.2

rope_apply in wan/modules/model.py:40 only rotates the first F*H*W tokens via x_i = torch.cat([x_i, x[i, seq_len:]]) — anything appended past the video grid is bare. Fix: monkey-patch via ContextVar so the splice receives continuous-position rotation.

FIX HMAC URL: workspace NAME, not UUID

Prior 'feedback_acp_hmac_permission_scope' said HMAC submit was permission-scoped out. Empirically wrong — substituting workspace UUID 019d9523-... in URL returns 403; substituting the literal name p1-video-world-model-for-robot-learning returns 200. Memory updated.

FAIL round-1 jobs SUCCEEDED with zero training

pt-njuem6ta and pt-jbdxz0er finished in 4 min each, ACP marked SUCCEEDED, final.pt saved — but inner train loop never iterated. len(ds)=1 + 4-rank DDP + drop_last=True yields 0 batches. Trap: 'SUCCEEDED' from ACP doesn't mean training succeeded; always verify per-step JSON in train.log.

FAIL round-2 OOM at step 11 (D) and 70 (A)

Both jobs printed 'expandable_segments not supported on this platform' at startup. Allocator fragmented under fp64-complex128 RoPE temps until process held 79.04/79.18 GiB and a 200 MiB allocation failed. Lower B helps but doesn't stop the slow leak; periodic torch.cuda.empty_cache() does.

FINDING arm A r2 had clean overfit signal pre-OOM

70 steps of pt-4bqjo86s shows joint 0.12 -> 0.05, add_s 0.88 -> 0.075, total 1.31 -> 0.17 — strong evidence the v1 paper-faithful path actually works once memory is stable. r4 with --empty-cache-every 25 should reach the full 2000 steps.
