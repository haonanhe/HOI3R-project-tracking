Key discoveries

FIX Trained-clip joint_l2 47.40 → 4.51 mm (arm-A) / 2.61 mm (arm-D) on the same checkpoint task

Both arms re-trained for 2000 steps under the same single-seq overfit recipe as pt-npwu0we6/pt-v9h8pfvl, but with the 2026-04-29 train↔eval sampler bug and the 2026-04-30 MANO-in-dataloader bottleneck both removed. The trained-clip eval number is now within √3× of training joint_l1 (≈5 mm/coord), confirming the model genuinely converged. Held-out and OOT numbers are essentially unchanged from the buggy baseline because those were always real OOD failures, not measurement artifacts.

FIX Dataloader: ~1000× speedup by routing through DexYCBGTCachedClip

Probe 2026-04-30: live DexYCB16FrameClip (MANO forward + textured_simple.obj reparse + JPG/PNG decode + depth→pts3d per frame) median 60 ms with 16-65 sec spikes per worker prefetch refill; cached DexYCBGTCachedClip median 2 ms with no spikes. Wall-clock for 4×H100 cl=81 single-seq overfit dropped from ~3 hr (pt-npwu0we6) to 31 min (pt-35iflrs6 arm-A) / 58 min (pt-eh1b7upj arm-D).

FINDING Cross-subject generalization (single-seq → subject-07) is unchanged at ~163 mm

arm-A OOT joint_l2 = 163.54 mm (rot 64.90°), arm-D OOT joint_l2 = 163.37 mm (mesh 159.51 mm, rot 66.33°). Both ~163 mm — matching the previous buggy baseline (162 mm). The 24× rotation-error explosion on OOT also persists in both arms. Single-seq training simply does not produce a model that generalizes across subjects; this is an architectural / data limit, not a measurement artifact. Multi-seq training is the next experiment.

FINDING arm-A vs arm-D: anatomical layout marginally beats frame on the trained clip

arm-D's anatomical query bank (per-joint + per-mesh-vert tokens with GPS-encoded identity) reaches joint_l2 = 2.61 mm vs arm-A's per-frame layout at 4.51 mm on the trained clip. arm-D additionally produces a 32-vert mesh (mesh_l2 ≈ 3.92 mm). On held-out and OOT splits the two arms are statistically tied. With a single-seq training set this is more capacity-vs-overfit story than a fair comparison — the multi-seq retrain will be the actual A/B.

Caveats

  • Single-sequence overfit baseline — not a model-quality benchmark. The 2.6 / 4.5 mm numbers prove the pipeline is correctly fitting the data and the eval is correctly measuring it; absolute generalization numbers will come from the multi-seq retrain.
  • arm-D was trained with n_mesh=32 (default in v2ablate_D.sh override at submit time), not the n_mesh=64 the trainer defaults to. Eval driver was passed --n-mesh 32 to match.
  • Both eval drivers (p2_eval_thfm_lora.py + p2_eval_thfm_lora_frame.py) had to be patched today to use THFM pad-or-clip — strict non-overlapping cl=81 emitted 0 windows for the 57-72-frame DexYCB sequences.
  • viz only renders 21-joint hand + posed object; arm-D's 32-vert mesh head output is not visualized in v1.
  • RGB-camera-view overlay video still missing per the project rule. P1 follow-up.
  • All code changes (DexYCBGTCachedClip extension, _thfm_lora_main routing, eval-driver patches) are uncommitted on the worktree as of this publish.

Bug-fix retrain results — trained-clip joint_l2 47 → 4.5 / 2.6 mm

Two retrains at cl=81, NPROC=4 BATCH=1, 2000 steps, single-sequence overfit on 20200709-subject-01/20200709_141754 (replicated 64×). Both runs route through the patched DexYCBGTCachedClip pipeline — no MANO forward, no OBJ-file reparse, no per-frame JPG/PNG decode at training time. Wall-clock dropped from ~3 hr (live loader) to arm-A 31 min / arm-D 58 min.

  • Trained clip joint_l2: 47.40 → 4.51 mm (arm-A frame layout) / 2.61 mm (arm-D anatomical, mesh_l2 also 3.92 mm) — matches the √3 × ~5 mm/coord-L1 prediction from training joint loss.
  • Held-out same-subject (4 seqs, mean): arm-A 125.30 mm, arm-D 130.17 mm — similar to the buggy-baseline numbers because those failures were always real OOD (single-seq overfit, no cross-sequence transfer).
  • OOT (subject-07, 5 seqs, mean): arm-A 163.54 mm, arm-D 163.37 mm — ~163 mm both arms; same-cross-subject cliff as before.
