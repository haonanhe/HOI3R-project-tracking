Key discoveries

FINDING Cached pyramid path skips all mini-evals (0/7)

p2_train.py short-circuits the in-loop p2_mini_eval.run_mini_eval when --cached-feats is set, logging mini_eval_skipped reason=encoder=wan22_cached at every scheduled step. Mini-eval requires a live encoder forward; restoring it for cached runs is Phase-4 work.

FINDING Wall time dominated by data + head, not encoder

110 min / 15 000 steps = ~440 ms/step at 8×H100 with bs=64 effective. Cache lookup eliminates the 0.6-1.0 s/step ViT forward seen on 4RC live runs; remaining cost is pyramid gather + head forward + Kabsch GT fit.

FINDING ADD-S converges to ~5.8 mm aggregate; rot error sub-degree

3-sequence in-distribution mean: obj ADD-S 5.85 ± 0.28 mm, rot 0.93 ± 0.31°, trans 5.65 ± 0.51 mm. Object pose head is well-converged. Hand metrics (vert 23.7, joint 22.5 mm) are an order higher; the gap reflects the training-loss-vs-metric definition gap (hand point loss is per-token weighted distance, eval is per-frame mean L2).

FINDING pt-wr11kin9 logs are empty on disk

Direct training-loss curve comparison against the 4RC live anchor is not possible — the launcher's tee buffering left logs/hoi3r_v2_p2_4gpu/seed0/train.log empty. Only ACP wall-time + args.json survive for that run.

Training-vs-eval drift

Final training-loss values at step 14 950 (taken from history.json) compared to the full-sequence eval aggregates from eval/aggregate.json. Predicted eval L2 = training MAE × √(2π/3) ≈ 1.38× (L2 vs L1 norm conversion factor for an isotropic Gaussian residual; rough ballpark, not a tight bound).

Interpretation. Object-pose metrics are nearly clean (eval drift ≈ 1.15× to 1.6×), but hand_joint shows a ~2.8× train-to-eval gap. This is consistent with a partial recurrence of the cached fp16 pyramid eval drift hypothesis (memory feedback_cached_pyramid_eval_gap.md): the 2.8× here is much smaller than the 16× reported in earlier P1 runs (where train and eval used different feature paths), but still meaningful. Hypotheses worth listing for follow-up:

  • (a) The hand head reads the cached pyramid more aggressively than the object head — multi-layer cross-attention into local+global feats may be more sensitive to fp16 quantization than the SE(3) regression that drives the object branch.
  • (b) Hand vertices in MANO space are dense (778 verts in a ~10 cm bounding sphere) and joint targets are sharply localised — sub-millimeter fp16 drift in the feature pyramid amplifies to centimeter-scale joint error.
  • (c) The eval forward path differs subtly from the train forward path (no DDP wrap, no EMA model, possibly different autocast scope) — even when the cache feed is identical the head module path may not be.

Net: object metrics validate the cached-pyramid swap; the hand-head drift is small enough to not be a blocker but large enough to be the primary target for the next diagnostic pass.

Caveats

  • Cached fp16 pyramid eval drift — per memory feedback_cached_pyramid_eval_gap.md: when train and eval use the IDENTICAL feature path the gap is small, but mixing the train-time fp16 cache with a fp32 live forward at eval has shown 16× regressions in past runs. Here both train AND full-seq eval use the same fp16 cache → fp32 cast, so this caveat is partially mitigated; the residual gap (eval hand_joint 22.5 mm vs final-train joint loss 0.006) reflects (a) train loss is per-token weighted distance, eval is per-frame mean-vert L2; (b) sampled CAD aug at train.
  • Photometric aug disabled — --photometric-on is incompatible with cached features (pre-encoder RGB perturbation cannot apply once features are frozen). The trainer asserts this on startup.
  • Mini-eval coverage = 0/7 — the in-loop p2_mini_eval.run_mini_eval requires a live encoder forward; the cached-Wan2.2 path skips all 7 mini-evals (mini_eval_skipped reason=encoder=wan22_cached at steps 2000/4000/6000/8000/10000/12000/14000). This is a known limitation tracked in scripts/hoi3r_v2/p2_train.py at the if use_cached: short-circuit on line 645.
  • pt-wr11kin9 logs empty — the 4RC live anchor's train.log is empty on disk due to tee buffering, so direct curve-vs-curve comparison isn't possible. Only ACP wall-time + args.json are available for that anchor.
  • Renderer fallback — scripts/hoi3r_offline_render.py --mode v3 requires a 4RC scene-NPZ that this run does not produce (no scene heads in the wan22 head-only checkpoint). Visualizations use scripts/render_world_space.py (world-space multi-frame + rotating MP4) instead. Camera-view overlay is deferred — would require a separate 4RC scene inference pass on the same frames.
  • Eval is on the TRAIN manifest — the 3 evaluated sequences are subset-of-train (subject-01-right, in the 50-sequence training manifest). This is in-distribution memorization eval, not held-out. Cross-subject hold-out eval is deferred to multi-subject manifest expansion.
